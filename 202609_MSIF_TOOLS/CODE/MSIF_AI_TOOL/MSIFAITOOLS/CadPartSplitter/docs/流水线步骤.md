# 「开始分割」步骤名对照（交流用语）

> 目的：把「点一下开始分割」以后实际发生的全部动作拆成 **18 个有名字的小步**。
> 交流时只要说「S06 遮表又吃掉零件了」「S16 清单二没出来」「S17 对表少 3 条」，
> 就能立刻定位到**是哪一步、看哪个文件、调哪个参数**。
>
> 这些名字**只用于人和人说话**：代码里没有 `S01` / 「遮表」这类标识符，
> 每一步下面写的「入口」才是真正的代码位置。
> 原理、算法依据、公式与案例复盘见 [分割原理.md](分割原理.md)（那边的阶段号 `[1]`…`[15]` 与本文有对照表，见第 3 节）。

**名字怎么记**

* **A 备料 / B 切图 / C 读数 / D 收工** —— 只用段名也能说清位置：

* **B 段是唯一真正决定零件框的段**（S03~S10）；**C 段只读、不参与框选**：关掉 S11~S17 里的任何一步，

* **清单一 / 二 里的「一 / 二」就是文件名前缀 `01_` / `02_`**，不用记别的。
* 说「S17 对表」而不是「Excel 那步」，因为它做的不是读 Excel，而是**拿 Excel 的部品表去对图纸**（生成 `tz.json` 供下游核报价）。

## 2. 逐步说明

每一步都按同一套格式写：**做什么 → 入口 → 输入/输出 → 怎么确认 → 出问题先看什么**。

### A 段 备料（每批一次）

#### S01 收料

* **做什么**：看输入框里给的是文件还是文件夹 —— 文件夹 → 批量（逐张），文件 → 单张；
  顺便把路径收拾干净（去掉资源管理器「复制为路径」带的引号、`file:///` 前缀、多行只取第一行），
  再定下「输出根目录 / 输出目录」，列出这一批要处理的 `.pdf`（按完整路径排序，处理顺序可复现）。
* **入口**：`MainForm`（「开始分割」按钮 → 单张 / `RunBatchAsync` 批量）、
  `CommandLineRunner.Run`（`Directory.Exists(args[0])` 判批量）、`BatchRunner.FindPdfFiles`、
  `DetectorOptions.GetDefaultOutputDirectory` / `GetDefaultBatchOutputDirectory` / `GetDrawingFolderName`。
* **输入 → 输出**：界面 / 命令行给的路径 → 待处理文件清单 + 输出目录（不存在会自动建）。
  省略输出目录时：单张 `<图纸目录>\AiAppData\<图纸名>[_P页号]`，批量 `<文件夹>\AiAppData\<图纸名>`。
* **日志**：`[INFO] 批量输入  ：…（仅当前文件夹）` / `[INFO] 找到 PDF  ：N 个` / `[INFO] 输出根目录：…`。
* **出问题先看什么**：
  - 文件夹里没 PDF → 界面弹窗「该文件夹下没有 PDF（只扫当前文件夹，不含子文件夹）」，
    命令行 `[WARN] 该文件夹下没有 PDF，未做任何处理。`；要连子文件夹得加 `--recursive`。
  - 只认 `.pdf`（比较扩展名时不分大小写，且不会把 `*.pdfx` 之类算进来）；扫描件是 `.tif/.png` 时得单张给。
  - **页码护栏**：批量里逐张查页数，某张 PDF 页数不够 → 该张直接失败并写明「页码 N 超出该 PDF 的页数」，
    不会静默换页。
  - 批量输出目录留空 = `<输入文件夹>\AiAppData`，每张图纸一个子文件夹 —— 与单张的树形完全一致。

#### S02 定参

* **做什么**：把界面控件 / 命令行开关翻译成一份 `DetectorOptions`，后面所有步骤都只读它；
  界面模式还会把参数立刻写进 `%APPDATA%\CadPartSplitter\settings.ini`（处理中途崩了也不丢）。
* **入口**：`MainForm.BuildOptions`、`GuiSettings`（读写 + 范围钳制 + `ApplyTo` / `FromOptions`）、
  `CommandLineRunner` 的参数解析（`--dpi` / `--area` / `--kw` / `--kh` …）。
* **输入 → 输出**：控件值 / 开关 → `DetectorOptions`（含日志回调 `Logger`：界面写日志面板，命令行写控制台）。
* **日志**：`[INFO] DPI=300  页码=0  遮蔽=0.50（自动=开）  最小面积=25000  边距=30  核=60×10`。
* **出问题先看什么**：
  - 参数越界 → 界面弹「参数错误」（`ArgumentOutOfRangeException`），不会带着错参数跑。
  - 「参数记住」不生效 → 看 `settings.ini` 是否可写（它在 `%APPDATA%`，不在 exe 旁边），删掉即恢复默认。
  - 命令行想复现界面的效果，对着 S04~S09 的参数名一条条对（见第 3 节对照表 + `分割原理.md` 第 4 节）。

### B 段 切图（每张图纸一次，决定所有零件框）

#### S03 栅格

* **做什么**：把输入变成一张彩色位图。PDF 用 PDFium 渲染到指定 DPI（透明背景合到白底），位图直接读。
* **入口**：`PartSplitterService.LoadImage` → `PdfRenderer.RenderPage` 或 `Cv2.ImRead`。
* **输入 → 输出**：文件路径 + `RenderDpi` + `PdfPageIndex` → BGR `Mat`（A1 @300 DPI ≈ 9933×7016）。
* **怎么确认**：`--debug` 下的 `debug_00_original.png` 就是这一步的结果。
* **出问题先看什么**：
  - A1 300 DPI 是约 7000 万像素（单通道 70 MB / 三通道 209 MB），批量跑多张时内存吃紧就先降 `--dpi`。
  - 整页全黑 / 全白 → `debug_00_original.png` 一看就知道，多半是 PDF 透明背景或加密 PDF。
  - `Unsupported format: .xxx` → 扩展名不在白名单（pdf / png / jpg / jpeg / bmp / tif / tiff）。

#### S04 净化

* **做什么**：灰度化 + 自适应**反向**二值化，让「墨迹 = 白（255）、纸面 = 黑（0）」——
  后面所有形态学操作都假设这个极性。
* **入口**：`PartDetector.Detect` 开头（`Cv2.CvtColor` → `Cv2.AdaptiveThreshold`）。
* **输入 → 输出**：BGR 彩色图 → 单通道 8UC1 二值图。
* **怎么确认**：`debug_01_binary.png`（黑底白线）。
* **参数**：`AdaptiveBlockSize`（默认 51）、`AdaptiveC`（默认 10）。
* **出问题先看什么**：
  - 线条糊成一片 / 淡线丢失 → `AdaptiveC` 调小、`AdaptiveBlockSize` 调大。
  - 噪点、污渍、扫描底灰进入前景 → `AdaptiveC` 调大。

#### S05 拆框

* **做什么**：擦掉图纸四周那条几乎贯穿全页的图框线。图框不擦有两个害处：与内部视图粘连成长条被当成零件；
  被遮蔽线截断后的残片反而躲过「外框占比」过滤，输出半页图。
* **入口**：`PartDetector` 的图框擦除（`RemovePageFrame`），擦除的行 / 列号记在 `_frameRows` / `_frameCols`，
  **导出时（S10）对彩色原图同步擦同样的行列**，所以成品 PNG 里也不带边框。
* **输入 → 输出**：二值图 → 擦完图框的二值图（行列号留到 S10 复用）。
* **参数与开关**：`RemovePageFrame`（默认开）、`PageFrameEdgeRatio`（0.10：只擦页边 10% 带内的线）、
  `PageFrameSpanRatio`（0.70：一行 / 一列要有 70% 幅面有墨迹才算图框线）；命令行 `--no-frame-erase` 关闭。
* **日志**：`[INFO] 导出图已同步擦除图框：横线 N 条 / 竖线 M 条`（在 S10 打）。
* **出问题先看什么**：
  - 零件图上还带着左 / 上 / 下边框、右边框却没有 → 曾经是「只擦二值图没擦原图」，现已同步擦；
    若又出现，先确认日志里那行「同步擦除图框」有没有打出来。
  - 零件自带的长中心线被当成图框擦掉 → `PageFrameSpanRatio` 调大或 `PageFrameEdgeRatio` 调小。
  - 整页被当成一个超大零件 → 图框没擦掉，先试 `--no-frame-erase` 对比。

#### S06 遮表

* **做什么**：把「表格 / 标题栏」从图上涂黑，让它们不参与后面的连通域。
  内部分两半：**探表**（读 PDF 文字层，推断出「只含文字的矩形」）→ **涂黑**（默认只涂这些矩形 = 块遮蔽；
  探不到 / 没有文字层时退回「整列遮蔽」或固定比例）。
  注意顺序：**探表在 S03 之后立刻就做**（它只要文字层 + 页面尺寸，不看像素），**涂黑在 S05 之后做**。
* **入口**：`PartTextExtractor.DetectTableAreas`（探表）→ `PartDetector` 的 `MaskTableAreas` / `MaskRight`（涂黑）。
* **输入 → 输出**：文字层 + 二值图 → 涂黑后的二值图；同时算出 `MaskStartX`
  （表格区左边界，S11 读文用它把框外文字分成「表格区 / 其它」）。
* **怎么确认**：`debug_02_masked.png` —— 块遮蔽时是**几个黑色矩形正好压住表格**，整列遮蔽时是**一条竖带**。
* **日志**：`表格遮蔽：按块遮蔽 N 块，表格区起点 X=…` / `右侧遮蔽：自动检出… X=…`；
  退回兜底时会写「自动检测失败 / 退回固定比例」。
* **参数与开关**：`MaskTableBlocks`（默认开）、`TableMaskPadding`（30 px，吃掉表格线框）、
  `AutoMaskRightColumn`（默认开）、`RightMaskRatio`（0.50，仅兜底）、`AutoMaskColumnInkRatio`（0.010）、
  `AutoMaskMinMaskedRatio` / `AutoMaskMaxMaskedRatio`（0.05 / 0.60，超出范围也退回兜底）；
  命令行 `--no-block-mask`（退回整列）、`--fixed-mask`（强制固定比例）、`--mask`、`--mask-ink`。
* **出问题先看什么**：
  - **同一张图上右侧的零件不见了**（典型：左右各一个「戸当り」只出一个）→ 遮蔽吃进零件区；
    先看 `debug_02_masked.png` 黑色区域边界，再调 `--mask`（调小）/ `--mask-ink`（调小）。
  - **表格残片变成假零件**（成品里多出一张表題欄或変更履歴表）→ `TableMaskPadding` 调大，或配合 S09 的 `TextHeavyRatio`。
  - **零件跨在遮蔽线上** → 日志 `[WARN] 有零件贴近遮蔽边界`，适当减小遮蔽比例。

#### S07 成团

* **做什么**：闭运算（2 次）+ 膨胀（1 次），用矩形核 `kw × kh` 把同一零件的碎散图元（轮廓、尺寸线、引出线、
  剖面线、文字）连成一团 —— 这是「一个零件 = 一个白色实心团」的来源。
* **入口**：`PartDetector` 形态学聚合段（`Cv2.MorphologyEx` / `Cv2.Dilate`）。
* **输入 → 输出**：涂黑后的二值图 → 膨胀图。
* **怎么确认**：`debug_03_dilated.png`。理想状态：**每个零件正好是一个白色实心团，团与团之间是黑的**。
* **参数**：`DilateKernelWidth`（60）、`DilateKernelHeight`（10）、`DilateIterations`（2）；命令行 `--kw` / `--kh`。
* **出问题先看什么**：
  - 上下两个视图粘成一张（如竖排 4 个断面部连成一张）→ `--kh` 调小（4~6）。
  - 左右相邻零件粘连 → `--kw` 调小。
  - 一个零件被切碎成好几块（尺寸标注没连上本体）→ 核调大。
  - 全页粘成一块 → 核过大或图框没擦干净（回 S05）。

#### S08 选框

* **做什么**：在膨胀图上取轮廓，用四道几何过滤把「像零件」的块挑出来：
  面积 ≥ `MinContourArea`、宽高 ≥ `MinBoundingWidth / MinBoundingHeight`、外接框填充比 ≤ `MaxBboxFillRatio`、
  不跨越遮蔽线；块遮蔽模式下另外丢掉「整块落在表格列带里」的残片（`_tableBandStartX`）。
* **入口**：`PartDetector` 轮廓筛选段（`Cv2.FindContours` + 过滤）。
* **输入 → 输出**：膨胀图 → 候选矩形列表（像素坐标）。
* **参数**：`MinContourArea`（25000）、`MinBoundingWidth` / `MinBoundingHeight`（200 / 80）、
  `MaxBboxFillRatio`（0.25，块遮蔽时放宽到 0.60）；命令行 `--area`。
* **出问题先看什么**：
  - 一个零件都没框出来 → 日志会打出 4 条检查建议（遮蔽 / 面积 / 膨胀核 / 调试图），
    按「S06 → S07 → S08」的顺序回看三张调试图最省事。
  - 细长杆 / 小零件被丢 → `--area` 调小、宽高下限放宽。
  - 孤立数字、噪点被当零件 → `--area` 调大。

#### S09 归并

* **做什么**：三件事，顺序固定 ——
  ① **加边距**：每个框四周 +`Padding`（防尺寸标注被切），clamp 到画布内；
  ② **重叠合并**：两框交集占小框 > `MergeOverlapThreshold` 就取并集，迭代到稳定（同一零件被切成两块时收回来）；
  ③ **残片筛除**（仅 PDF）：文字行合计面积占该块 ≥ `TextHeavyRatio` 的块判为「不是零件图」（表題欄 / 変更履歴表），丢弃，
  编号顺延不留空号。
* **入口**：`PartDetector` 的边距扩展 / 重叠合并 / `DropTextHeavyRects`。
* **输入 → 输出**：候选矩形 → 最终零件矩形。
* **日志**：`[RATIO] x=… 文字行占比 0.000`（仅 `--debug`，用来定阈值）、
  `[DROP] 文字行占比过高，判定不是零件图：…`、`文字行占比筛除：丢弃 N 个 / 保留 M 个（阈值 0.60）`。
* **参数与开关**：`Padding`（30）、`MergeOverlapThreshold`（0.30）、`DropTextHeavyParts`（开）、
  `TextHeavyRatio`（0.60）；命令行 `--pad`、`--keep-text-heavy`、`--text-ratio`。
* **出问题先看什么**：
  - 两个本该分开的零件被并成一张 → `MergeOverlapThreshold` 调大或 `--pad` 调小。
  - 同一零件留了两个框 → 阈值调小。
  - 表題欄 / 変更履歴表残片还在 → `--text-ratio` 调低（如 0.50）+ `TableMaskPadding` 调大。
  - 文字标注很密的**真零件**被误丢 → `--text-ratio` 调高，或 `--keep-text-heavy` 整体关掉筛除。
  - 别忘：筛除后如果全被丢光，会**全部保留**并打 `[WARN]`（避免输出为空）。

#### S10 裁切

* **做什么**：按 Y 升序编号 → 从**彩色原图**裁切（图框已按 S05 记下的行列同步擦掉）→ 存 `Part_01.png …`；
  同时把像素坐标换算成 mm 坐标（`mm = px × 25.4 / RenderDpi`，原点在页面左上），并写出坐标清单
  `parts_info.json`（`index` / `fileName` / `pixel` / `pdf_mm` / `callouts` / `texts`）。
* **入口**：`PartDetector.ExportParts` + `PartSplitterService.SavePartsJson`。
* **输入 → 输出**：最终矩形 + 彩色原图 → `Part_NN.png`（每张一条 `[SAVE]` 日志）+ `parts_info.json`。
* **日志**：`[SAVE] Part_01.png  (W×H px  Y=…)`、`[INFO] Coordinates saved: …\parts_info.json`。
* **出问题先看什么**：
  - 编号顺序和图上看的顺序不一致 → 只按 **Y 升序**排，同一水平线的两块谁先谁后不保证（要稳定就按 X 再判一次）。
  - 标注被切边 → `--pad` 调大；相邻零件重叠了 → 调小。
  - `[WARN] 保存失败：…` → 目标文件被别的程序占用（看图软件开着 PNG 也会占）。
  - `parts_info.json` 里 `texts` 是空的 → 正常，文字由 **S11 读文**回填（位图输入永远为空）。

### C 段 读数（每张一次；只读，不影响零件框）

> S11~S17 **都只读**，关掉任何一步都不会改变 `Part_NN.png` 与 `parts_info.json` 的坐标；
> 位图输入（png / jpg / tif）没有文字层，S11~S16 整体跳过（日志会说明原因），只有 S17 与输入格式无关。

#### S11 读文

* **做什么**：把 PDF 文字层的词按坐标归到各零件框里（`parts_info.json` 的 `texts` + `parts_text.txt` 清单）；
  **框外**的词按 S06 算出的 `MaskStartX` 分成「表格 / 标题栏区」与「其它未归属」，
  表格区再按「表 → 行 → 单元格」重组 → `outside_info.json` + `outside_text.txt`。
* **入口**：`PartTextExtractor.Attach` + `SaveTextReport` / `SaveOutsideJson` / `SaveOutsideTextReport`。
* **日志**：`[INFO] Text report saved: …` / `[INFO] Outside coords saved: …`；
  位图输入：`[INFO] 位图输入没有文字层，跳过文字坐标提取（如需识别文字请接入 OCR）。`
* **参数与开关**：`SplitTextToWords`（界面固定逐词，命令行 `--merge-text-lines` 改成按行合并）。
* **出问题先看什么**：
  - 清单里「（该图范围未检测到文字）」→ 扫描件 / 文字已转曲的 PDF，取不到文字层。
  - 日文乱码 → 文字层编码问题（PDF 本身），与 DPI 无关。
  - 某个零件的文字少 → 文字词的外接框与零件的重叠判定失败，通常是框太紧（S09 的 `--pad`）。

#### S12 圈号

* **做什么**：圈是矢量图形、不在文字层里，所以单独读 PDF 矢量路径找「整圆」，再拿文字层里落在圆心附近的数字配对，
  得到 ①1、②2 …，并按零件分组写清单（圆心 / 半径的像素、局部像素、mm 三种坐标）。
* **入口**：`CalloutExtractor.Extract` + `PartSplitterService.SaveCalloutsReport`。
* **产物**：`callouts.txt`（零件图内一段一段，框外的圈号归入最后一节）。
* **参数与开关**：`DetectCallouts`（默认开，命令行 `--no-callout` 关）、`CalloutMinRadiusMm`（0.8）、
  `CalloutMaxRadiusMm`（12.0）、`CalloutRadiusTolerance`（0.15）。
* **出问题先看什么**：
  - 圈号漏检 → 线粗 / 圈被压扁，`CalloutRadiusTolerance` 调大或半径范围放宽。
  - 把大孔 / 放大视图的圆当成圈号 → `CalloutMaxRadiusMm` 调小。
  - ①1 这种组合错位 → 圈内不止一个数字 / 数字不在圆心附近，属数据问题，清单里能看出是哪一个。

#### S13 抽表

* **做什么**：读 PDF 矢量路径里的横 / 竖框线 → 找「四面都被线围住」的矩形当单元格 → 用并查集把相邻单元格并成表 →
  再按文字层把字填进格子（行 / 列号是推断值）。
* **入口**：`RuledTableExtractor.Extract` + `RuledTableWriter.Save`。
* **产物**：`tables_info.json`（表 / 行 / 单元格结构）、`tables_text.txt`（人看的版式还原）、`tables\table_NN.csv`（机器读）。
* **日志**：`[INFO] 表格内容：该页没有识别到有线表格，不生成 tables_* 文件。`（识别到 0 张时）
* **参数与开关**：`ExtractRuledTables`（默认开，`--no-tables` 关）、`RuledTableMinLineMm`（2.0）、
  `RuledTableLineToleranceMm`（0.6）、`RuledTableMinCellMm`（2.0）、`RuledTableMaxRowGapMm`（120.0）。
* **出问题先看什么**：
  - 表格被切碎 / 列被并错 → `RuledTableLineToleranceMm` 与 `RuledTableMinLineMm` 两个容差配合调。
  - 双线框的细缝被当成单元格 → `RuledTableMinCellMm` 调大。
  - 上下两张表被并成一张 → `RuledTableMaxRowGapMm` 调小。
  - **这一步是 S14 / S15 / S16 的地基**：`tables\*.csv` 没有内容，后面三张清单基本都出不来。

#### S14 分类

* **做什么**：判这张图的图面分类（基本図 / 加工図 / アッセンブリ図 / 要領図）：规则是「在 `tables\*.csv` 的单元格里
  同时找到『PDF 文件名前 4 位』和四类关键字」，按 基本図 → 加工図 → アッセンブリ図 → 要領図 依次试。
  判完把结果合并进**整批一份**的 `classify\PdfInfoList.txt`（四列：図番号 / 文件名 / 图面分类 / 分类依据）：
  同一 `図番号` 就就地更新那一行，否则追加。
* **入口**：`PdfInfoListBuilder.Build`（判分类借 `DrawingListBuilder.Classify`）。
* **产物**：`<输出根目录>\classify\PdfInfoList.txt`（有表格没表格都写，没表格时分类留空）。
* **机制**：手工填过的行「分类依据」= `手工设定`，**重跑不会被自动判定覆盖**；自动判定这次没判出来的行，
  保留清单里上次的值（日志 `保留清单里上次的值`）。
* **参数与开关**：`BuildPdfInfoList`（默认开，`--no-pdf-info-list` 关）；界面按钮「图面分类清单…」可整份手工维护。
* **出问题先看什么**：
  - 分类空着 → **S15 / S16 全部不产出**。先点「图面分类清单…」手工填，比调参数快得多。
  - 分类明显错（把加工図判成要領図）→ 看「分类依据」列里命中的是哪个关键字，多半是表題欄写法不标准。

#### S15 清单一

* **做什么**：只有分类 = **アッセンブリ図** 的图纸才做，一次出两张：
  ① 部品表「下表参照」展开 → `01_アッセンブリ図_部品機能情報.csv`（部品コード 写着「下表参照」的行，
  按下一张参照表的明细条数展开）；② 要領図一覧 → `01_アッセンブリ図_要領図.csv`（項目 / 要領図漢字 / 図番 三列）。
* **入口**：`LtStep1Builder.Build` + `AssemblyYoryoBuilder.Build`（都在 `PartSplitterService.Run` 里、S14 之后）。
* **产物**：两张 `01_…csv`（都固定在图纸自己的输出目录里，不进 `classify\`）。
* **开关**：`BuildLtStep1Table` / `BuildAssemblyYoryoList`（命令行 `--no-lt-step1` / `--no-assembly-yoryo`）。
* **出问题先看什么**：
  - 两张都没出来 → 先查 S14 的分类是不是アッセンブリ図、再查 S13 有没有表格；
    分类不是アッセンブリ図时会**顺手删掉上一次留下的同名产物**（这是设计行为，不是丢文件）。
  - 明细条数不对 → 参照表没被识别成表（S13），或「下表参照」被写成了别的字样。

#### S16 清单二

* **做什么**：只有分类 = **要領図** 的图纸才做：把「品種 × 多列重复」的表摊平（一行一个部品），
  或把表头同含「部品名 + 枠区分 + 部品コード」的単純部品表摊平 → `02_要領図_部品機能情報.csv`（固定 5 列）。
* **入口**：`LtStep2Builder.Build`（`PartSplitterService.Run` 里的最后一个产物步骤）。
* **开关**：`BuildLtStep2Table`（默认开，`--no-lt-step2` 关）。
* **出问题先看什么**：
  - 文件没出来 → 分类不是要領図（回 S14）或这一步被关了。
  - 「品種」列空 → 块标题不在块起始列的正上方（合并单元格把标题写偏了）；`部品コード` / `員数` 仍然正确。
  - 「部品名」空 → 同上，看 `tables\table_NN.csv` 手工补。
  - 多出 / 少了行 → 表头认错（`品種` 出现在数据行里也会被当表头）。

#### S17 对表

* **做什么**：扫「图纸所在文件夹」里的 Excel（`.xls / .xlsx / .xlsm`，跳过 `~$` 临时文件与 `AiAppData` 里的产物），
  优先读名为 **`カメラ`** 的表（名字里带「カメラ」的也算；都没有就逐表按 5 列标题找），抽出
  `品種 / 部品名 / 枠区分 / 部品コード / 追加対応特注寸法` 五列，汇总成**整批一份**的 `classify\tz.json` 给下游核报价用。
  表头是「整张表往下找」的（不设深度上限），相邻 2~3 行拼、以及**同一列上下两行拼**（`追加対応` / `特注寸法`）都认。
  也有整张表不长成「5 列」的：`H310Z10004.XLS` 的 `カメラ` 表是**分块版式**
  （`① 三方枠` → `追加部品セット ： 片引戸用部品セット（ MZA674 ）` → 左右两组 `品種 / 追加対応特注寸法`），
  这时按块读：块见出し当 `枠区分`、`追加部品セット` 行给 `部品名` + `部品コード`、每组 `品種` 展开成一条明细。
  5 列找法一条都没收到时会自动再按分块版式读一遍（日志 `… 的「カメラ」表（分块版式）→ N 条明细`）。
* **入口**：`TzJsonBuilder.Build`（`BatchRunner.Run` 在逐张跑完之后调一次；单张 / 命令行在 `Run` 之后调一次）。
* **产物**：`<输出根目录>\classify\tz.json`（与 `PdfInfoList.txt` 同目录；UTF-8 无 BOM）；
  一个工作簿**一条明细都没收到**时，还会把它读到的工作表原样导到
  `<输出根目录>\classify\tz_debug\文件名__表名.csv`（最多 400 行 × 60 列）。
* **开关**：`BuildTzJson`（默认开，命令行 `--no-tz` 关；界面无开关，固定开）。
* **出问题先看什么**：
  - `tz.json` 没生成、或里面 `item_count` 是 `0` → **先打开 `classify\tz_debug\*.csv`**：那是这张表被读出来的原样，
    对着看「表头在第几行、五个列名到底怎么写」（`部品名` 写成 `品名`、`追加対応特注寸法` 拆成两行三格之类一眼就看见）。
    如果导出里根本没有那 5 个列名、而是 `① 三方枠` / `追加部品セット ： …（ MZA674 ）` / `品種` 这种分块版式，
    那是版式不同（不是列名写错），现在会自动按分块版式读；日志里能确认走没走到那一步。
  - 日志关键字：`文件夹里没有 Excel…`、`… 里没找到同时含 品種 / 部品名 / 枠区分 / 部品コード / 追加対応特注寸法 的表头`、
    `改按 5 列标题在全部 N 张表里找`、`读不动 xxx.xls（…）`、`诊断用表已导出 → …`。
  - 长版排错见 `README.md` 的「没有生成 `classify\tz.json` / 里面少了某些部品」一条。
* **注意**：它是**整批一份**，单张重跑也会按当次扫到的 Excel 重建；扫不到 Excel / 一条明细都没收到时**不写也不删**旧文件
  （以前会写出一份 `item_count: 0` 的空壳，现在改成不写、只记日志）。

### D 段 收工（每批一次）

#### S18 收工

* **做什么**：把这一批的结果汇总成人看得懂的一句话，并决定退出码 / 弹窗：
  - 批量：`[批量完成] 共 N 张：成功 X，失败 Y，零件合计 Z 个，耗时 …秒`，界面再弹一个汇总窗（有失败时附失败清单）；
  - 单张：`[DONE] 共分割零件 N 个 → <输出目录>`；没零件时提示「按上方提示调整参数后重试」；
  - 命令行 `--list` 时再顺手生成 `<输出根目录>\drawing_list.csv`（図番号 / 文件名 / 分类）；
    `--list-only` 则只做这一步、不分割。
* **入口**：`BatchRunner.LogSummary`、`MainForm`（状态栏 + 弹窗）、`CommandLineRunner`（退出码）、
  `DrawingListBuilder.Build`（`--list` / `--list-only`）。
* **退出码**：`0` 全部成功；`1` 参数 / 输入错误（文件不存在、用法不对）；`2` 有图纸处理失败。
* **出问题先看什么**：
  - 退出码 `2` 但界面上看着都成功 → 回去看 `[ERROR]` 那几行，是哪张、哪一步抛的异常（异常类型会写出来）。
  - 批量里某张失败不影响后面的图纸（单张失败隔离），所以「成功 9 / 失败 1」是正常形态，不是中断。
