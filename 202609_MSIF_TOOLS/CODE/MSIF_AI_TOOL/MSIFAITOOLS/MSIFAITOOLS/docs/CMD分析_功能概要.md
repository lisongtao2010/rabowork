# 【CMD 分析】按钮 —— 功能概要

> 适用：MSIFAITOOLS（.NET Framework 4.8，WinForms）
> 相关代码：`Form1.cs`（`BtnCmdAnalyze_Click`）、`Services/CmdPartAnalysisService.cs`（编排）、
> `Services/CmdAnalysisStep.cs`（**步骤名定义**）、`Services/CmdPartAnalyzer.cs`、
> `Services/CmdCalloutPartSplitter.cs`、`Services/CmdInstructionPartCollector.cs`、
> `Services/CmdTzPartCollector.cs`、
> `Services/PartAnalysisService.cs`（共用 `SelectAssemblyTargets` / `PartAnalysisSummary`）
>
> **步骤命名 / 沟通用语见 [CMD分析_步骤命名.md](CMD分析_步骤命名.md)**（点一次按钮 = 第 1 / 2 / 3 / 4 步）。

## 1. 一句话说明

【CMD 分析】是【AI 分析】之外的第二条入库通路：**不调用 AI**，直接读取 CadPartSplitter 在
【开始分解】时生成的 CSV 部品表，把「アッセンブリ図」的部品明细登录到与【AI 分析】**完全相同的
SQLite 表**（`PartBasicInfoRepository.TableName`）。

登录后还有三步后处理（**第 2 步 圈号拆分** / **第 3 步 要領図部品追加** / **第 4 步 tz.json 部品追加**，
旧称「阶段 A2 / 阶段 B」；都只针对 `classify\PdfInfoList.txt` 里「图面分类 = アッセンブリ図」的记录）：
**第 2 步 圈号拆分** —— 用部品行的「番号」在 `parts_info.json` 的 `callouts` 里找圈号（`text=4` / `display=④4`），
同一个部品在图上装了多处（不同零件图的 `texts` 互为包含）时，按排列方向给部品名加「右 / 左」「上 / 下」
并拆成多条；**第 3 步 要領図部品追加** —— 把各要領図里「品種与分类依据相符」的部品行、以及**没有品種（所有品種共用）**
的部品行一并挂到该装配图名下；**第 4 步 tz.json 部品追加** —— 读 Excel 部品表 `classify\tz.json`，
把「品種」与分类依据相符的明细（部品名 / 枠区分 / 部品コード / 特注寸法）也挂到该装配图名下。
入库方式、校验状态、部品信息画面的显示方式与 AI 分析一致。

### 步骤速查（详细说明见 [CMD分析_步骤命名.md](CMD分析_步骤命名.md)）

| 步 | 代号 | 名字 | 旧称 | 做什么 |
| --- | --- | --- | --- | --- |
| 0 | `S0` | 分解与分类 | —（按钮外） | 【开始分解】：CadPartSplitter + 本工具分解 + `classify\PdfInfoList.txt` |
| 1 | `S1` | 装配图部品入库 | 阶段 A | 读 `01_アッセンブリ図_部品機能情報.csv` → 建行 → `xy.txt` 校验 → 入库 |
| 2 | `S2` | 圈号拆分 | 阶段 A2 | 按 `parts_info.json` 的圈号把装配图部品按位置拆成多条 |
| 3 | `S3` | 要領図部品追加 | 阶段 B | 读 `01_アッセンブリ図_要領図.csv` → 各 `02_要領図_部品機能情報.csv` → 追加建行 |
| 4 | `S4` | tz.json 部品追加 | — | 读 `classify\tz.json` → 「品種」命中分类依据的明细 → 追加建行 |

点一次【CMD 分析】依次跑 **第 1 → 2 → 3 → 4 步**，日志里每步都带 `【第 N 步 · 名字】` 前缀
（名字来自 `Services/CmdAnalysisStep.cs`，改名字只改那一处）。

主按钮下面还有四个**子按钮**（第 1 步 / 第 2 步 / 第 3 步 / 第 4 步）：点哪个就只重跑哪一步，
日志首行变成 `执行步骤：仅 第 N 步 · 名字（分步执行）`。执行范围由
`CmdAnalysisStepKind` 传给 `AnalyzeAndSave`；按钮与代码的对应关系见 `docs/CMD分析_步骤命名.md` 第 8 节。

## 2. 前置条件与按钮校验（点下去先做的判断）

| 顺序 | 检查内容 | 不满足时的表现 |
| --- | --- | --- |
| 1 | 当前没有任务在跑（`_isRunning`） | 直接返回，不重复启动 |
| 2 | 已执行过【开始分解】，一览（`_classifications`）非空 | 弹窗「请先点击【开始分解】…」 |
| 3 | 分解输出目录 `_lastOutputDir` 存在 | 弹窗「找不到分解输出目录，请先执行【开始分解】」 |
| 4 | 一览中至少有一个「アッセンブリ図」 | 弹窗「【分类结果】中没有「アッセンブリ図」的 PDF」 |

通过后：把「アッセンブリ図」行做成**只读快照**（`PdfClassification` 副本，避免后台线程与界面并发），
切到【日志】页，`SetRunning(true)`，用 `Task.Run` 在后台执行 `CmdPartAnalysisService.AnalyzeAndSave`，
界面线程只负责把日志回调刷到日志框。

主按钮与四个子按钮共用同一个方法 `RunCmdAnalysisAsync(CmdAnalysisStepKind)`，
差别只在传进去的 `stepKind`（`All` / `Assembly` / `CalloutSplit` / `YoryoAppend` / `TzAppend`）——
校验、快照、日志、汇总、弹窗完全一样，所以单步执行的输出格式与一次跑完时一致。

## 3. 输入与输出

**输入**（全部由【开始分解】+ CadPartSplitter 产生，本功能只读）

| 文件 | 用途 |
| --- | --- |
| `<PDF 文件夹>\AiAppData\classify\PdfInfoList.txt` | 「図番,ファイル名,図面分類,分類根拠」；决定谁是要分析的 アッセンブリ図，以及「分类依据」原文（品種匹配用） |
| `<根>\<図番>\01_アッセンブリ図_部品機能情報.csv` | 装配图的部品表本体（多页时第 2 页起为 `<図番>_P2\…`）；旧名 `LT_STEP1.csv` 兜底 |
| `<根>\<図番>\xy.txt` | 文字坐标，用于交叉校验部品是否真的出现在图上（不存在则跳过校验） |
| `<根>\<図番>\01_アッセンブリ図_要領図.csv` | 该装配图引用的要領図 清单（項目 / 要領図漢字 / 図番） |
| `<根>\<要領図図番>\02_要領図_部品機能情報.csv` | 要領図 的部品明细（品種 / 部品名 / 枠区分 / 部品コード / 員数）；旧名 `LT_STEP2.csv` 兜底 |
| `<根>\<図番>\parts_info.json` | CadPartSplitter 的零件信息（零件框 + 文字 + 坐标）。`texts[]` 里的「A部 / F部 …」位置标记（第 3 步用）与 `callouts[]` 里的圈号 `text=4` / `display=④4`（第 2 步用）都用来给部品名加「右 / 左」「上 / 下」——只认 `index` 不同、且这些零件图的 `texts` 互为包含的零件图 |
| `<根>\classify\tz.json` | Excel 部品表转成的 JSON（品種 / 部品名 / 枠区分 / 部品コード / 追加対応特注寸法），第 4 步用 |
| `<根>\classify\PdfInfoList.txt` | 分类清单（図番号 / 文件名 / 图面分类 / 分类依据）；第 4 步从这里取「分类依据」与 tz.json 的「品種」比对 |

**输出**：只写 SQLite 部品基本信息表（唯一索引：図番 + ページ + 番号 + 部品コード）。
**不生成、不修改任何文件**（不写 CSV、不动 `AiAppData` 里的分解结果）。

**「数据来源」列**（`PartSourceKind`，数据库列名同为「数据来源」）：标明每行是哪个功能登录的 ——
第 1 步写 `CMD分析・アッセンブリ図`、第 3 步写 `CMD分析・要領図`、第 4 步写 `CMD分析・tz.json`；
【AI 分析】写 `AI分析`，
部品基本信息画面上手工追加的行写 `手工追加`。第 2 步只是把第 1 步的行拆条，**沿用原来的取值**。
老数据库（本版本之前建的表）打开时自动
`ALTER TABLE … ADD COLUMN` 补上该列，并按「来源表格文件」把老数据回填一次。

**「来源标识」列**（`PartSourceTag`，数据库列名同为「来源标识」）：上者的**简称**，用于在部品基本信息
画面上一眼区分这行部品来自**要領図**、**アッセンブリ図**本身的部品表、还是 **tz.json** ——
第 1 步写 `アッセンブリ図`、第 3 步（要領図）写 `要領図`、第 4 步写 `tz.json`、【AI 分析】写 `AI分析`、手工追加写 `手工追加`。
同样是后加的列，老库打开时自动补列并回填（先按「数据来源」换算，`数据来源` 为空的再按「来源表格文件」推断）。

## 4. 执行流程

### 阶段 A：按图纸登录部品（`CmdPartAnalyzer`）

对每个「アッセンブリ図」PDF 逐页读出 CSV，转成 `PartBasicInfo`：

1. **定位文件**：`<根>\<図番>\`（= 第 1 页）+ `<根>\<図番>_P2\_P3_…\`（按页码数值排序，
   `_P10` 排在 `_P9` 之后）。新名字取不到时自动回落旧名（老分解结果仍可用）。
2. **按列名映射，而不是按列号**（表头是图纸原表头，列序 / 列数不固定，可能带换行）：
   - 番号：`番号`
   - 部品名：`部品名 / 部品名称 / 品名 / 名称`
   - 部品コード：`部品コード / コード`
   - 部品図番：`部品図番 / 部品番号 / 図番 / 品番`
   - 枠区分：`枠区分 / 枠`、員数：`員数 / 数量 / 個数`
   - 基本寸法：`基本寸法 / 寸法`、切断寸法：`切断寸法 / カット寸法`
   先「完全一致」再「包含」匹配；匹配用文本会去掉空格 / 全角空格 / 换行。
3. **清洗**：跳过空行与重复出现的表头行；`番号` 解析不出来时按出现顺序补号；
   同一「页码 + 番号 + 部品コード」只保留一条（「下表参照」展开后完全相同的情况）。
4. **坐标校验**：读 `xy.txt` 建索引（`PartCoordinateVerifier`），逐行核对部品是否在图面文字里，
   结果写入 `PartVerifyStatus`（Passed / Failed），并在日志里输出一致 / 不符的条数。
5. **入库**：`PartBasicInfoRepository.Save(図番, parts)` —— 该図番原有行先删后插（整张覆盖），
   因此同一份数据重复执行不会翻倍。每行的「数据来源」写 `CMD分析・アッセンブリ図`、
   「来源标识」写 `アッセンブリ図`。

### 阶段 A2：按圈号分割部品（`CmdCalloutPartSplitter`）

対象図番来自 `classify\PdfInfoList.txt` 里「图面分类 = アッセンブリ図」的记录（清单读不到时退回一览），
再取该 図番 在部品基本信息表里的行，**只处理「来源标识 = アッセンブリ図」的行**（阶段 A 登录的行）：

1. **找圈号**：用行上的「番号」到该页目录的 `<根>\<図番>\parts_info.json`（第 2 页起 `<図番>_P2\`）里
   找 `callouts[]`，要求 `text`、`display`、`no` **三者自洽** —— 番号 4 必须命中
   `"text": "4"` + `"display": "④4"` + `"no": 4`；`display` 里的圈字符（①…⑳ / ⓪）与数字都要等于圈号，
   对不上视为圈号识别有误，该条 `callouts` 数据不采用。
2. **两条追加规则**（与阶段 B 的「A部」标记同一套，`PartsInfoIndex.BuildSplitPlan` 共用）：
   1. 命中的圈号必须来自 **`index` 不同**的零件图 —— 同一张零件图上出现多次仍算一处；
   2. 这些零件图的**全部 `texts`** 整体必须构成 `A ⊆ B` 或 `B ⊆ A` 的包含关系；
      互不包含（各自都有对方没有的文字）说明是不同零件，**不分割**。
3. **排列方向**：每张零件图取第一处，坐标用 `pdf_mm` 的圆心 `cx / cy`；
   X 方向跨度 ≥ Y 方向跨度 → 左右排列（`右 / 左`），否则上下排列（`上 / 下`），3 处再补「中」。
4. **拆条**：有几处就拆几条 —— 第 1 条沿用原「番号」，其余接在该図番**最大番号 + 1** 之后连续编号；
   部品名加方向前缀（`縦枠上部スペーサー` → `右縦枠上部スペーサー` + `左縦枠上部スペーサー`），
   备注追加 `位置：④4 右`（原备注非空时用 `；` 接在后面），其余字段（部品コード / 部品図番 / 員数 …）原样复制。
5. **写回**：有分割时 `repository.Save(図番, 全行)` 整张覆盖写（先删后插，所以必须提交全部行）；
   备注里已经带 `位置：` 的行**不再拆第二次**，重复执行不会让前缀叠加。

### 阶段 B：追加要領図 部品（`CmdInstructionPartCollector`）

要領図 部品建行 —— **有品種的按品種命中分类依据**；
**品種为空的行（`02` 是単純部品表 / 普通部品表，整张表也可能没有「品種」列）算「所有品種共用」的部品，一律登录**：

1. 用该装配图的「分类依据」原文（形如 `table_05.csv：H310 １７ラシッサ 片引戸 枠 アッセンブリ図`）
   与 `01_アッセンブリ図_要領図.csv` 里列出的每个要領図 図番 对应。
2. 打开该要領図 的 `02_要領図_部品機能情報.csv`，先收集文件里出现过的全部「品種」（非空），
   并统计「品種为空」的行数；**有品種的**用两份比对判定命中：
   - ① 把分类依据按空白 / 标点切成单词，与品種做**完全一致**比较（全角转半角、去空白、忽略大小写）；
   - ② 一个都没命中时退回**包含**比较（依据里各词可能没有分隔符）。
3. 只对「（品種命中 或 品種为空）+ 部品コード 有效」的行建行，同要領図 内
   「品種 + 部品名 + 部品コード」去重（共通行用固定键 `#共通`，不会吞掉同名同碼的有品種行）。
   **品種为空 ≠ 丢弃**：`02` 由単純部品表 / 普通部品表摊平时没有品種信息（表头甚至没有「品種」列），
   这些行是**所有品種共用**的部品 —— 一律登录，备注写 `品種：共通`；品種格里只写
   `―` / `-` / `／` / `・` / `共通` / `なし` / `無` 这类占位符时同样按共通处理（`IsBlankKind`）。
   （日志：`另有 N 行没有品種（共通部品），一并登录`；品種都不命中时
   `品種（…）都不在分类依据里 → 只登录无品種（共通）的 N 行`）。
   **部品コード 有效性**（`IsValidPartCode`）：去掉空白、全角转半角后必须至少含一个英文字母，
   因此**空、「―」「-」「／」等占位符、纯数字**的行一律丢弃（计入 `InvalidCodeRowCount`），
   日志提示 `要領図 <図番>：部品コード 为空 / 无效（不含英文字母）N 条，已跳过`。
   若该 `02` 文件没有「部品コード」列，则不做这个校验（退回「部品名或部品コード 非空即可」）。
4. **部品名的位置前缀**（`PartsInfoIndex`）——02 文件里没有「項目」列，項目 来自 01 要領図 清单：
   1. 取項目值的**第一项**并补「部」字：`A,M` → `A` → `A部`（`A` 也是 `A部`）；
   2. 到装配图的 `<根>\<図番>\parts_info.json` 里找文字正好是 `A部` 的记录，按 `pdf_mm` 取**文字框中心**，
      相距 1mm 以内的重复提取先合并成一处；
   3. **分割记录的追加规则**（避免把碰巧同名的标记当成两处而拆错）：
      1. 需找多条数据时，必须对应 **index 不同**的零件图 —— `index` 相同表示同一张零件图，出现多次也只算一处；
      2. 需找多条数据时，这些 index 下的**全部 text**（`texts[].text` 归一化后的集合）整体必须构成
         `A ⊆ B` 或 `B ⊆ A` 的包含关系（两两可比），只有这样的数据才允许分割记录；互不包含说明是不同零件，不分割。
         例：`Part_02` 的文字（`4` / `N部` / `A部` / `縦枠` / `M部` / `9.73`）⊇ `Part_03`（只少 `9.73`）→ 可分割；
         `Part_01`（`鴨居` / `F部` / `上レール` / `B部` …）与 `Part_09`（`Ｖレール` / `ツバ材` …）互不包含 → 不分割。
   4. 满足上面两条后，按不同零件图的代表点（每张零件图取第一处）判断排列方向：
      X 方向跨度 ≥ Y 方向跨度 → **左右排列**，否则**上下排列**；
      再按位置排序给部品名加前缀 —— 左右排列（X 从大到小）`右 / 左`、上下排列（Y 从小到大）`上 / 下`，
      3 处时补「中」（`右 / 中 / 左`、`上 / 中 / 下`）。
      例：`縦枠上部スペーサー` → `右縦枠上部スペーサー` + `左縦枠上部スペーサー`（各占一个番号、員数沿用 02 原值）；
   5. 只有 1 个零件图、零件图之间文字互不包含、`parts_info.json` 不存在（老分解结果）、
      或超过 3 个零件图（无法命名）时**不加前缀**，部品名原样；
      部品名为空时不加前缀。
6. 生成行的规则：

   | 字段 | 取值 |
   | --- | --- |
   | 図番 | アッセンブリ図 的図番（挂在装配图名下） |
   | ページ | 固定 1 |
   | 番号 | 接在已有行最大番号之后连续编号 |
   | 部品名 / 部品コード | 取自 02 文件（部品名可能带「右 / 左」「上 / 下」位置前缀，见本节第 4 点） |
   | 部品図番 | 要領図 的図番 |
   | 枠区分 | 取自 02 的枠区分列（単純部品表 / 普通部品表转来的 02 有该列；品種表转来的没有，留空） |
   | 員数 | 取自 02 的員数列（基本寸法 / 切断寸法 留空） |
   | 備注 | `品種：<品種>；項目：<項目>`（項目 来自 01 要領図 清单，多个时 `A / M`；品種为空时写 `品種：共通`） |
   | 校验状态 | `PartVerifyStatus.NotChecked`（要領図行不做坐标校验） |
   | 数据来源 | `PartSourceKind.CmdYoryo`（`CMD分析・要領図`） |
   | 来源标识 | `PartSourceTag.CmdYoryo`（`要領図`） |
   | 来源 | `SourceFile` = 02 文件路径，`PdfFile` = 装配图 PDF 路径 |

7. **再次入库**（幂等的关键）：先 `repository.Query(図番)` 取出该図番已有行，
   用 `IsYoryoPartFile`（`02_要領図_部品機能情報.csv` / 旧名 `LT_STEP2.csv`）**剔除上次追加的要領図行**，
   保留阶段 A 的装配图行，再合并本次要領図行后 `Save`（先删后插）。
   → 重复点按钮不会产生重复行，也不会丢掉装配图行。

### 第 4 步 · tz.json 部品追加（`CmdTzPartCollector`）

tz.json 是 Excel 部品表转成的 JSON，每行含 `品種` / `部品名` / `枠区分` / `部品コード` / `追加対応特注寸法`：

1. **対象**：`classify\PdfInfoList.txt` 里「图面分类 = アッセンブリ図」的记录，取其「分类依据」；
   清单里没有该図番时退回一览的 `Evidence`（都没有时日志提示 `没有分类依据…跳过`）。
2. **匹配**（与第 3 步同一套品種比对）：分类依据按空白 / 标点切词，与「品種」做完全一致比较
   （全角转半角、去空白、忽略大小写）；整词一个都不命中时才退回**包含**比较
   （日志 `tz.json：品種命中 N 条（命中品種 …，按包含比较命中）`）。
3. **丢弃规则**：`品種` 为空的行跳过（tz.json 没有「共通部品」的概念，日志 `没有品種的明细 N 条`）；
   `部品コード` 必须含英文字母（`IsValidPartCode`，空 / 纯数字跳过）；
   同一 `品種 + 部品名 + 部品コード` 只取一条。
4. **生成行的规则**：

   | 字段 | 取值 |
   | --- | --- |
   | 図番 | アッセンブリ図 的図番（挂在装配图名下） |
   | 页码 | 固定 1 |
   | 番号 | 接在已有行最大番号之后连续编号 |
   | 部品名 / 部品コード / 枠区分 | 取自 tz.json（員数 / 基本寸法 / 切断寸法 / 部品図番 留空） |
   | 备注 | `品種：<品種>；特注寸法：<追加対応特注寸法>`（没有特注寸法时只写 `品種：…`） |
   | 校验状态 | `PartVerifyStatus.NotChecked`（tz 行不做坐标校验） |
   | 数据来源 | `PartSourceKind.CmdTz`（`CMD分析・tz.json`） |
   | 来源标识 | `PartSourceTag.CmdTz`（`tz.json`） |
   | 来源 | `SourceFile` = `classify\tz.json` 路径，`PdfFile` = 装配图 PDF 路径 |

5. **再次入库**（幂等的关键）：先 `repository.Query(図番)` 取出该図番已有行，
   用 `IsTzRow`（`来源标识 = tz.json`）**剔除上次本步写入的行**，保留第 1 / 2 / 3 步的行，
   再合并本次 tz.json 行后 `Save`（先删后插）→ 重复点按钮不会产生重复行，也不会冲掉其他步骤的行。
   合并结果为空（该図番原本只有 tz 行、这次一条都不再命中）时改调 `ReplaceByDrawing` 把该図番清空
   ——`Save` 收到空表会直接返回、不清库，所以这一支必须单独处理。

## 6. 幂等性与容错

- **幂等**：第 1 步按図番整张覆盖写；第 2 步只拆备注里还没有 `位置：` 的行；第 3 步先剔除上次追加行再合并写；
  第 4 步先剔除上次写入的 `来源标识 = tz.json` 行再合并写 → 反复执行结果稳定。
- **缺文件不中断**：缺 01 csv / 01 要領図 清单 / 某个 02 文件时，只记一条提示并累加缺失数，
  其它 PDF 继续。
- **单文件异常隔离**：每个 PDF 的分析包在 try/catch 里，异常计入「失败」并输出错误日志，
  不影响后续 PDF；只有「输出目录不存在 / AI 配置」这类整体性错误才会中断。
- **界面不卡死**：分析在后台线程跑，日志通过回调回到界面；运行期间按钮区被 `SetRunning` 禁用。
- **查看结果**：分析完成后在【分类结果】选中一行 →【部品信息】，即可看到该図番登录的全部明细
  （含第 3 步追加的部品図番 / 備注里的品種）。

## 8. 已知边界（使用注意）

1. **要領図行挂在アッセンブリ図 的図番名下**（`部品図番` = 要領図 図番）。若希望挂到要領図 自己的図番下，
   只需改 `CmdInstructionPartCollector.CollectFromYoryoParts` 里 `assembly.Stem` 一处。
2. 若某张装配图的「分类依据」里**没有任何品種 词**：有品種的行**整张跳过**
   （日志：`品種（…）都不在分类依据里，跳过`）；但该 02 里**没有品種（共通）**的行仍会登录
   （日志：`品種（…）都不在分类依据里 → 只登录无品種（共通）的 N 行`）。
3. 要領図行**不做坐标校验**（`NotChecked`），因此在部品信息画面里不会显示「坐标一致 / 不符」。
4. 旧名兜底只在「新名字文件不存在」时生效：同一个 `<図番>` 目录里新旧两份都在时，用新名字那份。
5. `01_アッセンブリ図_要領図.csv` 的図番列是必需列；缺失时第 3 步直接跳过并提示表头内容。
6. `PartBasicInfoRepository.Save` 传入**空集合时直接返回 0、不执行删除**，所以「本次解析出 0 行」
   （或第 1 步判定无部品数据）时会保留该図番的历史数据，不会把旧记录清空。
7. 「部品コード 必须含英文字母」的过滤**只作用于 02（要領図）**；第 1 步的 01（アッセンブリ図）
   仍按原规则收集全部明细行（如需同样过滤，可在 `CmdPartAnalyzer` 的建行处复用 `IsValidPartCode`）。
8. **位置前缀只改部品名**：拆条后 `部品コード` 不变、「番号」连续递增（唯一索引仍然成立）；
   員数 / 枠区分 沿用 02 文件原值，**不按处数拆分**（2 处不会把員数 1 变成 0.5 / 2）。
9. 「項目」只取**第一项**：`A,M` 只按 `A部` 处理，`M` 不参与
   （如需 `A` / `M` 各自成行，需改 `CmdInstructionPartCollector.BuildItemMark`）。
10. `parts_info.json` 不存在（老分解结果 / 本机没跑 CadPartSplitter）时只是**不加前缀**：
    不提示、不报错，部品名与以前完全一样。位置标记只认**不同 `index` 的零件图**（同一张图里出现多次算一处），
    且这些零件图的全部 `texts` 必须整体构成 `A ⊆ B` / `B ⊆ A` 的包含关系，不满足时同样不加前缀
    （日志会写明 `但零件图（index …）的文字互不包含`）。
11. 「数据来源」「来源标识」都是**后加的列**：老数据库第一次被打开时自动补上
    （`PartBasicInfoRepository.EnsureColumn`），并回填一次 ——
    「数据来源」按「来源表格文件」推断（`02_要領図_…` → 要領図、`01_アッセンブリ図_…` → アッセンブリ図、
    `plu_table.txt` → AI 分析）；「来源标识」先按「数据来源」换算，仍为空的再按同一条文件规则兜底。
    认不出来的（手工录入等）保持空。
12. **第 2 步只认 `parts_info.json` 的 `callouts`**：老分解结果没有 `callouts`、或圈号的
    `text` / `display` / `no` 三者对不上时**不分割**，部品名原样（日志里也不提示，避免噪音）。
    另外 `callouts` 里的 `pdf_mm` 是**圆心** `cx / cy`，不是文字框的 `x / y / w / h`。
13. 拆出来的**第 1 条沿用原「番号」**，其余用「该図番最大番号 + 1」递增 ——
    所以同一部品的多条在部品信息画面里可能分列在番号首尾（不是连续编号）；
    想按部品看全部位置时按 `部品コード` 排序或筛选更直观。
14. 第 2 步的対象来自 `classify\PdfInfoList.txt`（不只看本次一览里的 PDF）：
    清单里列了但这次没分解的図番也会被处理（数据库里有旧行时）。
15. **`02` 里没有品種的行不会被丢弃**：`02` 由単純部品表 / 普通部品表摊平时没有品種列，
    这些行按「所有品種共用」登录（备註 `品種：共通`；品種格里只有 `―` / `-` / `／` / `共通` /
    `なし` 等占位符时同样算共通），日志里与「品種命中」分开计数
    （`品種命中 x 行 + 无品種（共通）y 行`）；同一部品既有品種行又有共通行时各留一条
    （去重键不同：`<品種>#名#码` 与 `#共通#名#码`）。
