# 【CMD 分析】步骤命名（沟通用语）

> 适用：MSIFAITOOLS（.NET Framework 4.8，WinForms）
> 步骤名的**唯一代码定义处**：`Services/CmdAnalysisStep.cs`（`CmdAnalysisSteps`）
> 编排实现：`Services/CmdPartAnalysisService.cs`；按钮事件：`Form1.cs`
> （主按钮 `BtnCmdAnalyze_Click` = 一次跑完；子按钮 `BtnCmdStep1_Click` / `BtnCmdStep2_Click` / `BtnCmdStep3_Click` / `BtnCmdStep4_Click` = 只跑一步）
> 功能细节（字段映射 / 判定规则 / 全部日志）：`docs/CMD分析_功能概要.md`

## 1. 这份文档解决什么问题

点一次【CMD 分析】，程序其实埋头做了 **4 件事**，以前在口头和文档里叫「阶段 A / 阶段 A2 / 阶段 B」，
说起来容易混（也看不出先后依赖）。现在给每一步起一个**短名字**，以后沟通直接说名字或代号即可：

- 「第 3 步（追加）没生效」→ 一看就知道是 02_要領図_部品機能情報.csv 那条通路；
- 「第 4 步（tz.json）没生效」→ 一看就知道是 `classify\tz.json` 按「品種 → 分类依据」匹配那条通路；
- 日志里每步都有前缀 `【第 N 步 · 名字】`，日志和说法一一对应；
- 每一步都写清了「怎么单独验证」，排查时不用整条链路重跑。

> **按钮**：主按钮【CMD 分析】仍然**一次跑完 4 步**（`S1 → S2 → S3 → S4`），行为没变；
> 它下面多了四个**子按钮**，点哪个就只重跑哪一步（单步调试 / 重试用，见第 8 节）。

## 2. 步骤总表

| 步 | 代号 | 名字（正式） | 口头简称 | 一句话说明 | 主要输入 | 主要输出 |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | `S0` | 分解与分类（按钮外） | 准备 | 【开始分解】跑 CadPartSplitter + 本工具分解，生成分类清单 | `<PDF 文件夹>` | `AiAppData\*\`、`classify\PdfInfoList.txt` |
| 1 | `S1` | 装配图部品入库 | 入库 | 读 01_アッセンブリ図_部品機能情報.csv → 建行 → xy.txt 校验 → 入库 | `01_アッセンブリ図_部品機能情報.csv`、`xy.txt` | `部品基本信息` 表（装配图行） |
| 2 | `S2` | 圈号拆分 | 拆分 | 按 parts_info.json 的圈号把装配图部品按位置拆成多条 | `parts_info.json`（`callouts`） | 同表（部品名加「右 / 左」「上 / 下」） |
| 3 | `S3` | 要領図部品追加 | 追加 | 顺着要領図清单读各 02 文件，把要領図 的部品挂到装配图名下 | `01_アッセンブリ図_要領図.csv`、`02_要領図_部品機能情報.csv` | 同表（`来源标识 = 要領図` 的行） |
| 4 | `S4` | tz.json 部品追加 | tz 追加 | 读 Excel 部品表 `classify\tz.json`，把「品種」命中分类依据的明细挂到装配图名下 | `classify\tz.json`、`classify\PdfInfoList.txt`（分类依据） | 同表（`来源标识 = tz.json` 的行） |

四步都写进**同一张表**：`部品基本信息`（SQLite，默认 `<程序目录>\Data\MSIF_Parts.db`）。

## 3. 逐步说明

> 每一步都能**单独执行**：点【②  执行】区第二行对应的子按钮即可（主按钮仍是一次跑完 4 步）；
> 也可以用下面的 SQL 直接查库确认某一步有没有写成功。

### 第 0 步 · 分解与分类（`S0`，按钮外）

- **做什么**：点【开始分解】时，先调用 CadPartSplitter（`Part_NN.png` / `parts_info.json` / `tables\*.csv` 等），
  再由本工具自己做 xy / table / plu 文本分解，最后读上游写的分类清单 `classify\PdfInfoList.txt`，
  得到每张 PDF 的「图面分类」。只有分类为 **アッセンブリ図** 的 PDF 才会进入后面 4 步。
- **日志关键字**：`PDF 文件夹：` / `待处理 PDF：` / `分类统计：`
- **失败的表现**：第 1 步日志出现 `跳过：找不到 …\01_アッセンブリ図_部品機能情報.csv`
  → 说明这步没勾「先调用 CadPartSplitter」，或该 PDF 的图面分类不是 アッセンブリ図。
- **怎么单独验证**：看 `AiAppData\classify\PdfInfoList.txt` 里该図番的「图面分类」列；
  看 `AiAppData\<図番>\` 下有没有 `01_アッセンブリ図_部品機能情報.csv` / `parts_info.json` / `01_アッセンブリ図_要領図.csv`。

### 第 1 步 · 装配图部品入库（`S1`）

- **做什么**：对每个目标 PDF，定位 `01_アッセンブリ図_部品機能情報.csv`（兼容旧名 `LT_STEP1.csv`），
  按列名映射建行（番号 / 部品名 / 枠区分 / 員数 / 基本寸法 / 切断寸法 / 部品コード），
  用 `xy.txt` 做坐标校验（`坐标一致` / `坐标不符` / `未校验`），然后整図番「先删后插」入库。
- **日志头**：`【第 1 步 · 装配图部品入库】读 01_アッセンブリ図_部品機能情報.csv → 建行 → xy.txt 校验 → 入库（N 个 PDF）`
- **逐行日志**：`[i/N] CMD 分析：<文件名>` → `  提示：…` → `  登录成功：N 条（図番 …）`
- **代码**：`CmdPartAnalyzer.LocateSources` / `Analyze`；入库 `PartBasicInfoRepository.Save`。
- **怎么单独验证**：把该図番的行按 `来源标识 = アッセンブリ図` 查出来，看行数与日志 `登录成功：N 条` 是否一致。

### 第 2 步 · 圈号拆分（`S2`）

- **做什么**：只处理**第 1 步写入的行**（`来源标识 = アッセンブリ図`）。用行上的「番号」到该页
  `parts_info.json` 的 `callouts` 里找圈号（`text=4` / `display=④4`，两者要自洽）；圈号必须出现在
  **index 不同**的零件图里，且这些零件图的 `texts` 整体互为包含（`A ⊆ B` / `B ⊆ A`），
  才按坐标判排列方向（左右 / 上下）给部品名加「右 / 左」「上 / 下」并拆成多条。
- **日志头**：`【第 2 步 · 圈号拆分】按 parts_info.json 的圈号（callouts）把「アッセンブリ図」的部品行按位置分割（K 个図番）`
- **逐行日志**：`  分割：番号 3（④4）在 parts_info.json 中 2 个零件图里出现、左右排列 → 部品名加「右」（1 行 → 2 条）`
  / `  番号 5（…）… 但无法命名 → 不分割` / `  没有需要按位置分割的部品`
- **幂等**：备注里已带 `位置：` 的行不再拆第二次。
- **代码**：`CmdCalloutPartSplitter.Split`；判定 `PartsInfoIndex.ResolveCalloutSplit`。
- **怎么单独验证**：查该図番里部品名带「右 / 左」「上 / 下」的行；或看备注里是否出现 `位置：④4 右`。

### 第 3 步 · 要領図部品追加（`S3`）

- **做什么**：读装配图的 `01_アッセンブリ図_要領図.csv`（項目 / 要領図漢字 / 図番）→ 对每个要領図図番
  读 `02_要領図_部品機能情報.csv`（品種 / 部品名 / 枠区分 / 部品コード / 員数）→
  「品種命中分类依据」的行 + 「品種为空（共通部品）」的行建行，番号接在该図番已有最大番号之后，
  备注写 `品種：xxx；項目：A,M`（共通部品写 `品種：共通`）→ 与第 1 / 2 步的行合并后整図番覆盖写。
- **日志头**：`【第 3 步 · 要領図部品追加】01_アッセンブリ図_要領図.csv → 各要領図的 02_要領図_部品機能情報.csv，把品種命中分类依据的部品（含没有品種的共通部品）挂到「アッセンブリ図」上`
- **逐行日志**：`  要領図 <図番>：品種命中 2 行 + 无品種（共通）1 行 / 命中品種 …` →
  `  要領図部品登录：5 条（図番 …，该図番合计 42 行），其中无品種（共通）2 条` / `  没有需要追加的要領図部品`
- **幂等**：先剔除上次本步写入的行（`来源表格文件` = 02 文件）再合并，重复执行不会产生重复行。
- **代码**：`CmdInstructionPartCollector.Collect` / `CollectFromYoryoParts`；`CmdPartAnalysisService.CollectInstructionParts`。
- **怎么单独验证**：查该図番 `来源标识 = 要領図` 的行；看 `备注` 是否 `品種：…`、`部品図番` 是否要領図図番、
  `枠区分` / `員数` 是否与 02 文件一致。

### 第 4 步 · tz.json 部品追加（`S4`）

- **做什么**：读 `classify\PdfInfoList.txt` 里「图面分类 = アッセンブリ図」的**分类依据**，
  再读 `classify\tz.json`（Excel 部品表转成的 JSON：品種 / 部品名 / 枠区分 / 部品コード / 追加対応特注寸法），
  把「品種」命中分类依据的明细挂到该装配图名下：番号接在该図番已有最大番号之后，
  备注写 `品種：…；特注寸法：…`（没有特注寸法时只写 `品種：…`），`来源标识 = tz.json`
  （`数据来源 = CMD分析・tz.json`）→ 与第 1 / 2 / 3 步的行合并后整図番覆盖写。
- **匹配规则**（与第 3 步同一套）：分类依据与「品種」都按空白 / 标点切词、全角转半角、转大写后比较；
  先试「整词完全相同」，全都对不上才退一步用「互相包含」（日志会写 `按包含比较命中`）。
  `部品コード` 必须含英文字母（空 / 纯数字的行跳过，日志 `部品コード 为空 / 无效（不含英文字母）N 条`）；
  `品種` 为空的行跳过（与第 3 步的「無品種 = 共通」不同，tz.json 没有共通行的概念）。
- **日志头**：`【第 4 步 · tz.json 部品追加】读 PdfInfoList.txt（图面分类 = 「アッセンブリ図」的记录，取分类依据）→ tz.json 中「品種」命中分类依据的明细挂到「アッセンブリ図」上`
- **逐行日志**：`  tz.json：N 条明细 / 清单里「アッセンブリ図」K 条` → `  tz.json：品種命中 x 条（命中品種 …）` →
  `  tz.json 部品登录：5 条（図番 …；该図番合计 43 行）`（重跑时多一段 `，已剔除上次 tz 行 K 条`）/
  `  没有需要追加的 tz.json 部品`
- **幂等**：先剔除上次本步写入的行（`来源标识 = tz.json`）再合并，重复执行不会产生重复行；
  同一 `品種 + 部品名 + 部品コード` 只取一条。该図番若原本只有 tz 行、这次一条都不再命中，
  合并结果为空，改用 `ReplaceByDrawing` 清空该図番（`Save` 空表不清库）。
- **代码**：`CmdTzPartCollector.ReadAssemblyEvidence` / `LoadEntries` / `Collect`；`CmdPartAnalysisService.AppendTzParts`。
- **怎么单独验证**：查 `来源标识 = 'tz.json'` 的行，备注应带 `品種：`；对照 tz.json 里同一品種的明细条数。

## 7. 单独验证某一步（SQL）

数据库：`<程序目录>\Data\MSIF_Parts.db`，表名 `部品基本信息`（可用任意 SQLite 工具打开，如 DB Browser for SQLite）。

```sql
-- 各步各写了多少行（アッセンブリ図 = 第 1 / 2 步，要領図 = 第 3 步，tz.json = 第 4 步）
SELECT 来源标识, COUNT(*) AS 行数
FROM 部品基本信息
WHERE 図番 = 'H310U10004'
GROUP BY 来源标识;

-- 第 1 步（装配图部品）
SELECT 番号, 部品名, 枠区分, 員数, 部品コード, 校验状态
FROM 部品基本信息
WHERE 図番 = 'H310U10004' AND 来源标识 = 'アッセンブリ図'
ORDER BY 番号;

-- 第 2 步（圈号拆分的结果：部品名带方向、备注带「位置：」）
SELECT 番号, 部品名, 备注
FROM 部品基本信息
WHERE 図番 = 'H310U10004' AND 备注 LIKE '%位置：%'
ORDER BY 番号;

-- 第 3 步（要領図部品：部品図番 = 要領図図番，备注 = 品種：…）
SELECT 番号, 部品名, 枠区分, 員数, 部品コード, 部品図番, 备注
FROM 部品基本信息
WHERE 図番 = 'H310U10004' AND 来源标识 = '要領図'
ORDER BY 番号;

-- 第 4 步（tz.json 部品：备注 = 品種：…；特注寸法：…）
SELECT 番号, 部品名, 枠区分, 部品コード, 备注
FROM 部品基本信息
WHERE 図番 = 'H310U10004' AND 来源标识 = 'tz.json'
ORDER BY 番号;
```

界面上等效操作：【分类结果】选中该 PDF → 点【部品信息】→ 按「来源标识」列分辨是哪一步写的行。

## 8. 分步执行：主按钮 + 4 个子按钮（已实现）

界面上现在有 **1 个主按钮 + 4 个子按钮**，两者走同一套代码，只是传给服务层的「执行范围」不同：

| 按钮 | 传给服务层的值 | 跑哪几步 | 日志里的执行步骤行 |
| --- | --- | --- | --- |
| 【CMD 分析】（主按钮，位置不变） | `CmdAnalysisStepKind.All` | 第 1 → 2 → 3 → 4 步（一次跑完，行为与以前一致） | `执行步骤：共 4 步 —— 第 1 步 · … → 第 2 步 · … → 第 3 步 · … → 第 4 步 · …` |

要点：

1. **名字只有一处**：子按钮文字在 `Form1` 构造函数里由 `CmdAnalysisSteps.ButtonText(kind)` 设置，
   与日志里的 `【第 N 步 · 名字】` 同源；改名字只改 `Services/CmdAnalysisStep.cs`。
2. **单步入口**：`CmdPartAnalysisService.AnalyzeAndSave(…, CmdAnalysisStepKind stepKind)`；
   原来的 3 参数版本保留（内部转成 `All`），旧调用不受影响。
3. **第 2 / 3 / 4 步有前置检查**：数据库里这些図番一行都没有时，只记一条警告
   `数据库中还没有这些図番的部品行，请先执行 第 1 步 · 装配图部品入库。` 并立即返回，不做任何写库。
4. **共用界面流程**：`Form1.cs` 的 `RunCmdAnalysisAsync(CmdAnalysisStepKind)` 负责校验 / 快照 / 后台执行 / 汇总；
   `SetRunning(true)` 期间四个子按钮一起置灰（文字不变）。
5. **单步执行不会冲掉其他步骤的数据**：第 2 步只重写「来源标识 = アッセンブリ図」的行
   （`CmdCalloutPartSplitter.Split` 把非装配行原样带回），第 3 步只重写「来源标识 = 要領図」的行
   （`CollectInstructionParts` 先 `RemoveAll(IsInstructionRow)` 再合并），第 4 步只重写「来源标识 = tz.json」的行
   （`AppendTzParts` 先 `RemoveAll(IsTzRow)` 再合并）；写库前都把该図番其余行一起提交。
