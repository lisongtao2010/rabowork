## 1. 一次「AI 分析」的调用链

```
PartAnalysisService.AnalyzeAndSave            （批量入口，日志：AI 提示语：外部文件：...）
 └─ AiPartAnalyzer.Analyze(pdf, plu_table.txt, xy.txt)
     ├─ PluTablePageLocator.SplitPages         拆分「--- 第 N 页 ---」
     ├─ PluTablePageLocator.FindCandidatePages 找同时含「番号」「部品名」的表头页 → 本例 [1]
     ├─ PluTablePageLocator.ExpandWithFollowingPages(+1 页, 最多 6 页) → 本例 [1]
     ├─ PluTablePageLocator.BuildTableSnippet  表格片段（上限 40,000 字符）→ 本例 12,337 字符
     ├─ XyCoordinateIndex.Load(xy.txt) + AiPartAnalyzer.BuildCoordinateSnippet
     │                                         坐标片段（每页 260 词、上限 20,000 字符）→ 本例 12,817 字符
     ├─ AiPromptStore.Load()                   读 bin\Debug\Prompts\AiPartAnalyzer.Prompt.txt
     ├─ AiPromptSet.BuildUserPrompt(図番, 表格片段, 坐标片段)   替换 {{DRAWING_NO}} / {{TABLE_TEXT}} / {{#COORDINATE}}
     ├─ ChatCompletionClient.Complete(system, user)
     │    └─ BuildRequestBody → POST /chat/completions（temperature=0, stream=false）
     └─ AiPartResponseParser.Parse(message.content) → RemoveDuplicates → VerifyWithCoordinates
```

本次实际尺寸：

| 项目 | 值 |
| --- | --- |
| system 提示词 | 71 字符 |
| user 提示词 | 25,792 字符（370 行） |
| 请求体 | 27,034 字符 / UTF-8 编码后 30,142 字节 |
| AI 回复 | 6,298 字符（外层 JSON） |
| 用量 | prompt 17,958 tokens / completion 3,357 tokens（其中思考 2,643）/ total 21,315 |
| 解析结果 | 12 行部品基本信息，`finish_reason = stop` |

> 思考型模型的输出长度会浮动：同一份输入再抓一次为 response 4,058 字符、completion 2,103 tokens，**解析出来的 12 行内容完全一致**。`temperature = 0` 保证结果稳定，变化的只是「思考」部分的长短。

### 4.1 模板正文 + 図番（第 1–14 行，原样）


## 7. 从这份真实对话里能看出的几个要点

1. **AI 完全按「原样保留」执行**：`MEA□□408`、`MZB○○963`、`MZB△△955` 的全角 □○△、`下表参照`、`-` 都被原样带回，没有被"修正"成猜测的编号。
2. **員数字段会出现类型代号**（`A` / `C` / `D` / `E` / `F` / `G`），这是图纸「タイプ名 → 員数」对照表的设计，AI 照原样取回，程序也不做数值化处理。
3. **表格文本噪声很大**（列错位、混入 `9.73`、`鴨居`、`G部`），但 AI 仍正确停在番号 12；第 2 条规则（番号必须连续）是关键约束，改动提示词时不要删掉。
4. **思考型模型会多花 token**：本例 prompt 17,958 + completion 3,357（思考 2,643）≈ 21,315 token。若在意成本，可把坐标段进一步压缩（`MaxCoordinateWordsPerPage = 260`、`MaxCoordinateSnippetChars = 20000`），或换用非思考模型。
5. **坐标段只是"核对用"**：提示词明确写了「坐标只用于核对，不要因为坐标而修改表格文字」，避免 AI 用坐标去改写表格文字。

## 8. 想再看自己的图纸与 AI 说了什么

```powershell
# 在项目目录（Tools 的上一级，即含 bin\Debug 的那一层）执行
powershell -NoProfile -ExecutionPolicy Bypass -File .\Tools\dump_ai_prompt.ps1 `
    -PdfPath "D:\...\testresult\H310U10004.pdf"

# 可选参数：-AppDir <MSIFAITOOLS.exe 所在目录，默认 ..\bin\Debug>
#          -OutDir <输出目录，默认 %TEMP%\msif_prompt_demo>

# 输出到 %TEMP%\msif_prompt_demo：
#   01_system.txt          送给 AI 的 system 消息原文
#   02_user.txt            送给 AI 的 user 消息原文（替换后的完整内容）
#   03_request_body.json   实际 POST 的请求体

#   05_ai_content.json     message.content（AI 给出的 JSON 结果）

```

脚本做的事和程序一模一样：先用 `PdfSplitService.Split` 分解 PDF（生成 `plu_table.txt` / `xy.txt`），再用 `PluTablePageLocator` + `AiPromptSet.BuildUserPrompt` 拼提示词，然后用 `ChatCompletionClient.BuildRequestBody` 拼请求体并真实 POST，最后用 `AiPartResponseParser.Parse` 解析。所以抓到的内容就是程序运行时真正发出的内容。
