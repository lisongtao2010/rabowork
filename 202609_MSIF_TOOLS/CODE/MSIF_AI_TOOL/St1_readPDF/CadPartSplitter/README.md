# CadPartSplitter — CAD 图纸零件自动分割工具

把一张工程图纸（PDF 或扫描图）自动切分成一个个独立零件图（PNG），
**并记录每张零件图的坐标、以及该图上所有文字及其坐标**，
用于后续 CAD 识别 / 报价流程。基于 **.NET Framework 4.8 + WinForms + OpenCvSharp4 + Docnet.Core(PDFium) + PdfPig**。

## 运行

双击 `CadPartSplitter.exe` 启动图形界面；带参数启动则进入命令行模式（供批处理调用）。

### 图形界面

1. **输入文件**：点「浏览…」选择 `.pdf / .png / .jpg / .bmp / .tif`（也可直接把文件拖到窗口上）
2. **输出目录**：选择图纸后自动填为 `<图纸名>_parts`，可手工修改
3. **识别参数**：一般保持默认即可；识别效果不理想时按下表调整
4. 点「开始分割」，日志面板会实时显示每一步进度，完成后状态栏提示零件数量

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 渲染 DPI | 300 | PDF 渲染分辨率。降低可省内存，但细节会变模糊 |
| 页码 | 0 | 多页 PDF 指定页（从 0 开始） |
| 右侧遮蔽 | 0.50 | 屏蔽右侧 BOM 表/说明区。**开启「自动遮蔽」时仅作兜底比例** |
| 自动遮蔽 | 开 | 自动定位表格/标题栏的起始列，按实际表格位置遮蔽。关掉则退回固定比例 |
| 筛除表格残片 | 开 | 文字行合计面积占该块 ≥ 60% 的块判定为「不是零件图」（表題欄 / 変更履歴表等），直接丢弃 |
| 最小面积 | 80000 | 轮廓面积阈值，滤掉孤立数字/噪线 |
| 扩展边距 | 30 | 裁切框四周留白，防止尺寸标注被切 |
| 核宽度 / 核高度 | 80 / 25 | 形态学膨胀核，用于把同一零件的碎散图元聚合在一起 |
| 保存调试图 | 关 | 额外输出二值图、遮蔽图、膨胀图，便于定位参数问题 |

> 文字清单的粒度（`parts_text.txt` 默认一个词一行）在界面上没有开关，固定为逐词；
> 需要「同一水平线上的词拼成一句」时请改用命令行加 `--merge-text-lines`。

### 命令行

```
CadPartSplitter.exe <输入文件> [输出目录] [选项]
```

| 选项 | 说明 |
| --- | --- |
| `--debug` | 保存中间处理图 |
| `--dpi <N>` | PDF 渲染 DPI（默认 300） |
| `--page <N>` | PDF 页码，从 0 开始（默认 0） |
| `--mask <N>` | 右侧遮蔽比例 0.0 ~ 1.0（默认 0.50，自动检测失败时的兜底） |
| `--fixed-mask` | 关闭自动遮蔽，强制按 `--mask` 的固定比例遮蔽（旧行为） |
| `--mask-ink <N>` | 自动遮蔽的列墨迹阈值（图高比例，默认 0.010） |
| `--no-block-mask` | 关闭「按表格块精确遮蔽」，退回整列遮蔽（排查用） |
| `--no-frame-erase` | 关闭「图框擦除」（排查用） |
| `--no-callout` | 关闭「圈号标注识别」（①1、②2 …） |
| `--keep-text-heavy` | 保留文字行占比过高的块（默认丢弃表題欄 / 変更履歴表等表格残片） |
| `--text-ratio <N>` | 文字行面积占比判定阈值（默认 0.60） |
| `--merge-text-lines` | 文字清单按行合并（默认一个词一行，各自带自己的坐标） |
| `--area <N>` | 最小轮廓面积（默认 80000） |
| `--pad <N>` | 外接框扩展像素（默认 30） |
| `--kw <N>` / `--kh <N>` | 膨胀核宽度 / 高度（默认 80 / 25） |
| `-h` / `--help` | 打印用法 |

示例：

```
CadPartSplitter.exe drawing.pdf output --debug
CadPartSplitter.exe scan.png parts --mask 0.48 --area 50000 --fixed-mask
CadPartSplitter.exe plan.pdf result --dpi 200 --kw 60 --kh 20
```

退出码：`0` 成功（含「未检测到零件」）、`1` 输入文件不存在、`2` 处理异常。

## 处理流程

```
输入 PDF/图片
   ↓ 灰度化 + 自适应反向二值化（线条 → 白色前景）
   ↓ 擦除四周图框（贯穿页边的长横线 / 长竖线）
   ↓ 定位表格区域并遮蔽：
        · PDF 有文字层 → 用文字的行列结构推断「表格 / 表題欄」矩形，只涂黑这些矩形
        · 否则 → 自动定位右侧表格/标题栏起始列（列墨迹延伸法），刷黑整条竖带
        · 再失败 → 按「右侧遮蔽」比例兜底
   ↓ 形态学闭运算 + 膨胀（聚合同一零件的碎散图元）
   ↓ 外层轮廓提取 + 面积/宽高/边界筛选（块遮蔽时另丢弃表格残片）+ 重叠矩形合并
   ↓ （仅 PDF 有文字层）表格残片筛除：文字行合计面积占该块 ≥ 60% → 判定「不是零件图」并丢弃
        · 零件图上的文字只有零散尺寸标注，行框占自身外框很小；表題欄 / 変更履歴表整块都是文字行
        · 在导出 PNG 之前丢弃，输出编号仍然连续（不会留下空号）；可用 --keep-text-heavy 关闭
   ↓ 按 Y 坐标排序裁切 → Part_01.png, Part_02.png, …
        · 裁切取自原始彩色图前，先把上面擦掉的图框线一并涂白（范围完全一致），
          否则输出图会带着图纸的左 / 上 / 下边框而缺右边框，看起来像「整页被竖切一刀」
   ↓ （仅 PDF，只读）读取文字层：框内文字 + 坐标 → texts / parts_text.txt
   ↓ （仅 PDF，只读）框外文字（表格 / 标题栏 / 页边注记）+ 表格行列结构 → outside_info.json / outside_text.txt
   ↓ （仅 PDF，只读）识别「圈号标注」：矢量路径里找整圆 + 文字层找圆内数字 → ①1、②2 … → callouts.txt
```

每一步的原理、算法依据、参数影响与调参顺序，见 **[docs/分割原理.md](docs/分割原理.md)**。

### 表格残片筛除（文字行合计 ≥ 60% 就不是零件图）

表格的线框若没被完全遮蔽，会剩下一条横条连通域，被当成零件输出 —— 图里没有零件视图，只有
表題欄 / 変更履歴表的几行字。这类块用「文字占比」一眼可分：

```
文字行占比 = Σ(整页每条文字行的外接框 ∩ 该块) ÷ 该块面积
```

文字行按 `parts_text.txt` 里同一套规则分组（同一行的词并成一个矩形），所以「行框」就是
那行字实际占的矩形。表格每一行都横跨单元格、行行相邻，行框几乎铺满整块；零件图上的文字
只是零散尺寸 / 引线注记，加起来占不了多大面积。

| 块 | 实测（300 DPI） |
| --- | --- |
| 真正的零件视图（`H310U10004.pdf` 11 张、`H310A20009.pdf` 2 张） | 0.03 ~ 0.46 |
| 表題欄 / 変更履歴表 残片（`H310U10004.pdf` 2 块） | 0.65 / 0.72 |

默认阈值 **0.60**，≥ 阈值即在导出 PNG 之前丢弃（编号顺延，不留空号），日志：

```
[DROP] 文字行占比过高，判定不是零件图：x=674 y=6212 w=1419 h=156 文字行占比 0.65
[INFO] 文字行占比筛除：丢弃 2 个 / 保留 11 个（阈值 0.60）
```

- 位图输入没有文字层，本规则不生效（不做 OCR）。
- 全部候选都被判定为文字块时会**保留原样并告警**，避免输出为空。
- 想看每个块的实测占比：加 `--debug`，日志会打印 `[RATIO] … 文字行占比 0.xxx`。
- 文字标注特别密集的零件视图（实测最高 0.46）若被误丢，把阈值调高：`--text-ratio 0.70`；
  反之想更激进地清理，调低到 `0.50`。

## 输出

```
<输出目录>/
├─ Part_01.png          # 按从上到下顺序编号的零件图
├─ Part_02.png
├─ parts_info.json      # 每个零件的像素坐标 + PDF 毫米坐标 + 该图上的文字及坐标
├─ parts_text.txt       # 人眼可读的文字清单（每张图一节：图坐标 + 图上的文字，默认一个词一行；圈内的数字显示为 ①1）
├─ callouts.txt         # 圈号标注清单（圆圈 + 圈内数字，①1 ②2 …，含圆心 / 半径 / 坐标）
├─ outside_info.json    # 被分割部分以外：表格区「表→行→单元格」+ 其它未归属文字（含坐标）

   debug_01_binary.png
   debug_02_masked.png
   debug_03_dilated.png
```

### parts_info.json（机器可读）

每个零件一条，`texts` 为该图上所有文字（PDF 词级，未合并）。文字坐标同样给三套：
`pixel`（页面绝对像素）、`local`（相对该零件图左上角）、`pdf_mm`（页面毫米）。
`callouts` 为该图上的圈号标注（圆圈是矢量图形、不在文字层，故单独识别）：`no` / `text` /
`display`（`①1`）/ `circle`（圆心 `cx,cy` + 半径 `r`，页面像素）/ `pixel`（圆外接框）/
`local`（圆心相对该图左上角）/ `pdf_mm`（圆心 + 半径的毫米值）。
非 PDF 输入时 `texts`、`callouts` 均为空数组，其余字段与旧版本一致。

### parts_text.txt（人眼可读）

**一个词一行**：每行给一个 PDF 词的文字 + 它自己的外接框（绝对 / 局部坐标），
顺序是「自上而下、行内从左到右」，所以同一水平线上的几个词会相邻排成几条，
一眼能看出「它们原本在同一行」，但各自带着自己的框。
**被圈住的数字（圈号标注）会按它原来的位置显示成带圈形式**（`1` → `①1`），
同一行里其它相同数字（尺寸、数量）不受影响：

```

# 生成时间   : 2026-11-01 12:52:30
# 源文件     : D:\…\H310U10004.pdf
# 页面 / DPI : 第 1 页 / 300 DPI
# 坐标说明   : 绝对 = 页面像素坐标（左上原点）；局部 = 相对该零件图左上角；mm = 页面毫米坐标
```

> 想要旧行为 —— 同一水平线上的词拼成一句、只给并集坐标（`①1 鴨居 G部`）——
> 加 `--merge-text-lines` 即可；此时节标题会标成「（按行合并）」，文件头也多一行
> `# 文字粒度 : 按行合并…`。拼行规则是「纵向中心差 ≤ 0.6 × 字高」，
> 只是这种形式下几个词共用一个并集框，下游分不清每个词各自的框。
> `outside_text.txt` 第二节「其它未归属文字」与这里同粒度。

> 带圈替换的判定方式是**按坐标**：圈内那个数字词的中心必须落在圈内（≤ 0.95 倍半径）且文本相符，
> 所以「同一行里既有圈号 ②2、又有尺寸 20」时只会改被圈住的那一个；匹配依据是
> `parts_info.json` 里的 `texts` 坐标，而 `texts` 本身保留词级原始文本（仍是 `1`）。
> 圈号在零件图外、或该词不在零件框内时无法替换，日志会给
> `[WARN] Part_NN.png：圈号 N 个，其中 M 个未在该图的文字中定位到圈内数字 …`。

> 文字取自 PDF 文字层，因此扫描件 / 文字已转曲的 PDF 取不到文字（`texts` 为空、清单标注
> 「（该图范围未检测到文字）」）；`□` 等以矢量图元绘制的符号也会缺失。
> 详见 [docs/分割原理.md](docs/分割原理.md) 3.8 与第 5 节。
>
> 上面这份清单是 11 张：该图纸底部原本还有 2 条表題欄 / 変更履歴表残片，已被
> 「文字行占比 ≥ 60%」规则丢弃（见上节「表格残片筛除」），
> 所以 `Part_01` … `Part_11` 全是真正的零件视图。

### callouts.txt（圈号标注清单）

图纸上的「圈 1 / 圈 2」这类引出编号：**圆圈是矢量图形（不在文字层），只有圈里的数字在文字层**，
所以直接复制文字只能得到孤立数字。本工具把两者配成一条记录，输出带圈的 ① ② … 与坐标：

```
# CadPartSplitter 圈号标注清单（矢量圆圈 + 圈内数字）
# 合计       : 10 处（零件图内 10 / 零件图外 0）

[Part_01.png]  圈号 7 个  绝对(x=0 y=0 w=1334 h=2479)
    ①1     圆心(cx=958 cy=213 r=21px/1.8mm)  局部(957,213)  外接框(x=936 y=192 w=43 h=43)
    ⑤5     圆心(cx=471 cy=462 r=21px/1.8mm)  局部(471,462)  外接框(x=450 y=441 w=43 h=43)

[Part_02.png]  圈号 3 个  绝对(x=1532 y=936 w=1783 h=866)
    ③3     圆心(cx=1611 cy=1082 r=21px/1.8mm)  局部(79,146)  外接框(x=1590 y=1060 w=43 h=43)
```

**圈号在 `parts_text.txt` 里是怎么体现的**（同一份识别结果，两处呈现）：

* **词记录替换**：圈内那个数字词在原位置变成 `①1`（逐词一行时那一条就是 `①1`；
  加 `--merge-text-lines` 时是整句里替换：`1 鴨居 G部` → `①1 鴨居 G部`），
  按「词中心落在圈内」匹配，同处其它数字不受影响；
* **每节末尾清单**：另列一段 `── 圈号标注（圆圈 + 圈内数字）——`，给出 ①、圆心、半径、坐标。

`parts_info.json` 的 `texts` 保持词级原始文本（`1`），需要真值时以 JSON 为准。

识别方式（细节见 [docs/分割原理.md](docs/分割原理.md) 3.10）：

* **找圆**：读 PDF 页面的矢量路径，把每条子路径扁平化成折线后判定「整圆」——
  包围盒近正方（宽高比 ≥ 0.90）、各点到圆心的半径比 ≤ 1 + `CalloutRadiusTolerance`、
  八个方位全被覆盖（排除圆弧 / 圆角）、半径在 0.8~12mm 之间。
  无论是「四段贝塞尔曲线」画的圆还是「大量短直线」折线画的圆都能识别；
* **配对**：圈内必须有一个 1~3 位纯数字词（文字层），且数字尺寸装得进圈（高 ≤ 1.3 倍半径）；
* **归属**：按圆心落在哪张零件图的框内分组，所以同一页不同视图里重复的 ①② 不会混淆。

> 位图输入、扫描件（无矢量路径 / 无文字层）无法识别，`callouts.txt` 会写「未识别到」。
> 日志会逐条打印 `[CALLOUT] ①1  Part_01.png  圆心(958,213) r=21px=1.8mm  局部(957,213)`。

### outside_info.json / outside_text.txt（被分割部分以外）

零件框以外的文字也在同一套坐标系里留档，分两类：

* **表格 / 标题栏区文字**：词中心 X ≥ 遮蔽线（日志 `右侧遮蔽：自动检出表格/标题栏区 X=7074`）
  的词，按「表 → 行 → 单元格」重组——同一水平线（纵向中心差 ≤ 0.6 倍字高）为一行，
  行内与前一个词的水平间隙 > `max(24px, 1 倍字高)` 就断开成新单元格，列号是表内按
  单元格中心 X 聚类的推断值；

## 排错

- **检测不到零件**：日志会列出 4 项检查建议（遮蔽比例 / 面积阈值 / 膨胀核 / 调试图），先开「保存调试图」看 `debug_03_dilated.png` 是否把零件糊成了一整块。
- **一张图被切成一半 / 右侧视图不见了**：多数是遮蔽吃进了零件区。默认「块遮蔽」只涂黑文字层推断出的表格矩形（日志 `表格遮蔽：按块遮蔽 N 块，表格区起点 X=…`），正常不会切到零件；若仍出现，先看 `debug_02_masked.png` 里黑色矩形是否压到了视图，再用 `--no-block-mask` 对比整列遮蔽的效果。图框相关的问题可用 `--no-frame-erase` 排除。
- **输出的零件图里带着图纸边框线（左 / 上 / 下边框在、右边框没有，像是整页被竖着切了一刀）**：导出裁切用的是原始彩色图，而图框擦除原本只作用于检测用的二值图。现已同步擦除（日志 `导出图已同步擦除图框：横线 N 条 / 竖线 M 条`），擦除范围与检测阶段一致（±2px），只动图框那几行 / 几列像素。
- **图纸右侧的零件没被切出来（例如同一张图上画了两个「戸当り」，只出一个）**：说明右侧零件落在了遮蔽区内。整列遮蔽时会按表格/标题栏的实际起始列遮蔽（日志 `表格遮蔽`/`右侧遮蔽：自动检出… X=…`），若日志显示退回了固定比例，或图纸右侧确实有很宽的表格区，请调小「右侧遮蔽」（如 0.30）或把 `--mask-ink` 调小。
- **多出一张只有表格的图（表題欄 / 変更履歴表 / 部品表）**：说明表格块的线框没被完全遮蔽，残留成一个横条连通域。默认已按「文字行合计 ≥ 60% 就不是零件图」把这
  类块丢弃（日志 `[DROP] 文字行占比过高…` / `[INFO] 文字行占比筛除：丢弃 N 个`）。若仍出现，加 `--debug` 看该块的 `[RATIO]` 实测值：
  占比低于 0.60 就用 `--text-ratio` 调低阈值（如 0.50）；同时可把 `TableMaskPadding` 调大（默认 30px）让块遮蔽多吃掉些表格线框。
  反过来，若某个零件视图被误丢，把 `--text-ratio` 调高，或用 `--keep-text-heavy` 整体关闭该筛除。
- **分不清表格区与图纸区**：`--fixed-mask` 可强制沿用固定比例遮蔽（旧行为），配合 `debug_02_masked.png` 直接看遮蔽边界位置。
- **多个视图被切在一张图里**（如竖排 4 个断面部连成一张）：它们被基准线 / 中心线连成了一团。可减小 `--kh`（如 4~6）后重跑，或在消费端按空白带自行再切。
- **零件被截断**：出现 `[WARN] 有零件贴近遮蔽边界` 时，说明有零件跨越了遮蔽线，适当减小「右侧遮蔽」比例。
- **PDF 报 `BadImageFormatException`**：输出目录里的 `pdfium.dll` 位数与进程不匹配。本项目固定为 x64，`CadPartSplitter.csproj` 中已显式设置 `Prefer32Bit=false` 与 `DocnetRuntime=win-x64`；若改过平台目标，请同步这两项。
- **`parts_text.txt` 里没有文字、或坐标整体偏移**：前者多为扫描件 / 文字已转曲的 PDF（无文字层，日志会提示 `该页没有文字层`，此时也不会生成 `outside_*`）；后者多为页面 `/Rotate` 旋转或 CropBox 偏移，日志会出现 `N/M 个词换算后落在画面外` 警告。`□` 这类以矢量图元绘制的方框一定取不到，属正常现象。
- **`outside_info.json` 里表格被切得太碎 / 粘成一张**：分表靠「垂直间隙 + 相邻行单元格数突变」两条启发式（3.9）。单元格数突变阈值是代码常量 `PartTextExtractor.CellCountJumpTol`（默认 2）；列数多的表若被误切，把它调大。
- **圈号（①1、②2）一个都没识别出来**：日志出现 `圈号标注：页面未发现圆形图形` 时，多为扫描件（无矢量路径）或圈是用「图片 / 文字字符」画的；出现 `读取 PDF 矢量路径失败` 时是 PdfPig 解析不了该页图形。还有一种常见情形是圈画得比 `CalloutMaxRadiusMm`（默认 12mm）还大——A0/A1 大图幅偶尔如此，调大该参数即可。
- **圈号识别到一些不该有的（大孔、放大视图被当成圈）**：先把 `CalloutMaxRadiusMm` 调小（如 5~6mm），再必要时把 `CalloutRadiusTolerance` 调小（如 0.08）收紧圆度；实在干扰可用 `--no-callout` 整体关闭（不影响分割结果）。
- **圈号有圈但没配上数字**：圈内数字若不是 1~3 位纯数字（例如 `A`、`イ`、`⑤` 这种已经在文字层里带圈的字符），本工具不会配对，属预期行为。
- **`callouts.txt` 里识别出了圈号，`parts_text.txt` 里却还是裸数字**：说明那个数字词没在对应的零件图文字里定位到（日志 `[WARN] Part_NN.png：圈号 N 个，其中 M 个未在该图的文字中定位到圈内数字`）。常见原因是圈号跨在零件框边界上（该词按 50% 重叠率归到了零件图外）或数字被识别成非纯数字；此时以 `callouts.txt` / `parts_info.json` 的 `callouts` 为准。用 `--no-callout` 可完全关掉替换与清单。

## 项目结构

| 文件 | 职责 |
| --- | --- |
| `Program.cs` | 入口：无参数启动 GUI，带参数走命令行 |
| `MainForm.cs` / `MainForm.Designer.cs` | 图形界面与布局 |
| `CommandLineRunner.cs` | 命令行参数解析与输出 |
| `PartSplitterService.cs` | 「加载文件 → 检测分割 → 落盘」流程封装，GUI 与 CLI 共用（PDF 先推断表格块，再检测；写 `parts_info.json` / `parts_text.txt` / `callouts.txt` / `outside_info.json` / `outside_text.txt`） |
| `PdfRenderer.cs` | PDF → OpenCV Mat（Docnet.Core / PDFium） |
| `PartDetector.cs` | 核心图像处理与零件裁切：二值化、图框擦除、表格遮蔽（块 / 列 / 固定比例）、形态学、轮廓筛选、合并、文字行占比筛除（`DropTextHeavyRects`）（`MaskStartX` 对外暴露表格区起点） |
| `PartTextExtractor.cs` | 读 PDF 文字层：`DetectTableAreas` 推断表格 / 表題欄矩形；框内按重叠率归属各零件图 → 分行（`GroupIntoLines`）→ 逐词（`BuildWordLines`，默认）/ 按行（`BuildLines`）整理清单；框外分「表格区 / 其它」并重组成表→行→单元格；`ReadTextLineBoxes` 提供整页文字行框供占比筛除 |
| `PartText.cs` | 词级文字坐标模型、清单行模型（`PartTextLine`）、表格行列模型、页面矩形 `PageRect`、页面文字结果模型 |
| `Callout.cs` | 圈号标注模型（圈内数字 + 圆心 / 半径 + 绝对 / 局部 / mm 坐标 + ① 显示形式） |
| `CalloutExtractor.cs` | 圈号识别：矢量路径找整圆（扁平化后判定圆度 / 方位覆盖）、与文字层数字配对、按零件图归属；`MarkCalloutWords` 按坐标把圈号回填到词上（供 `parts_text.txt` 替换） |
| `DetectorOptions.cs` | 全部可调参数 + 日志回调 |
| `docs/分割原理.md` | 分割原理技术说明（流水线、算法依据、调参、案例复盘、文字坐标换算） |

## 构建

```
msbuild CadPartSplitter.csproj /t:Restore /p:RuntimeIdentifiers=win-x64
msbuild CadPartSplitter.csproj /p:Configuration=Release /p:RuntimeIdentifiers=win-x64
```

> `Docnet.Core` 的 build targets 会按 RID 拷贝 `pdfium.dll`，若不指定 RID
> （或 `obj/project.assets.json` 里没有 `win-x64` 这一项）会报
> *"doesn't list 'win-x64' as a RuntimeIdentifier"*。首次构建、以及改过
> `PackageReference` 之后都需要带 `/t:Restore` 重新生成 assets。
> 另外重新构建前请先关闭正在运行的 `CadPartSplitter.exe`，否则 `bin\` 下的 DLL 会被占用。

依赖（NuGet，见 `CadPartSplitter.csproj`）：`OpenCvSharp4`、`OpenCvSharp4.runtime.win`、
`Docnet.Core`（渲染）、`PdfPig`（只读 PDF 文字层，用于文字坐标）。

## 自测脚本

`_test/gen_test_raster.ps1`（PowerShell 5.1+）生成一张合成图纸 `_test/test_raster.png`
（白底 + 两个粗线框"零件" + 右侧假表格），用于验证「位图输入」分支：

```
powershell -ExecutionPolicy Bypass -File _test\gen_test_raster.ps1
bin\Debug\CadPartSplitter.exe _test\test_raster.png _test\out --area 20000 --kw 40 --kh 10 --pad 10
```

`_test/callout_overlay.ps1` 用来核对圈号识别结果：读输出目录里的 `parts_info.json`，
把每条 `callouts` 的圆画成红圈 + 蓝色 ① 标签叠在对应的 `Part_NN.png` 上
（生成 `Part_NN_callouts.png`），一眼就能看出圈和数字是否配对正确：

```
powershell -ExecutionPolicy Bypass -File _test\callout_overlay.ps1 _test\verify_call_A20009
```

`_test/verify_callout_text.ps1` 校验「圈号是否按位置替换进了 `parts_text.txt`」：
读 `parts_info.json` 的每个圈号圆心，找出外接框包含该圆心的那条文字记录
（默认逐词一行时就是那个数字词本身；`--merge-text-lines` 时是整行），
检查该条文本里确实有对应的 `①1`，并打印「圈号 N 个，按位置命中带圈文本 M 个」：

```
powershell -ExecutionPolicy Bypass -File _test\verify_callout_text.ps1 _test\verify_call_A20009
```

`_test/PathProbe/`（需 .NET SDK 8+，仅开发参考、不参与主工程构建）是一个独立小探针，
用来查看某份 PDF 里「圈」的矢量路径是怎么画的（`dotnet run -- <pdf> <页> <宽> <高> circles`），
换用新图纸时若圈号识别不准，可先用它确认圈是「四段贝塞尔」还是「折线」、半径落在什么区间。
若本机 SDK 不是 10，请把 `PathProbe.csproj` 的 `TargetFramework` 改成本机版本。

表格残片筛除（文字行占比 ≥ 60%）可直接用命令行核对：`H310U10004.pdf` 默认应输出 11 张
（日志 2 条 `[DROP]` + `[INFO] 文字行占比筛除：丢弃 2 个 / 保留 11 个`），
加 `--keep-text-heavy` 应回到 13 张，加 `--debug` 会逐块打印 `[RATIO] … 文字行占比 0.xxx`：

```
bin\Debug\CadPartSplitter.exe H310U10004.pdf _test\out_drop
bin\Debug\CadPartSplitter.exe H310U10004.pdf _test\out_keep --keep-text-heavy --debug
```

位图分支应输出 2 张零件图，`parts_text.txt` 中标注「（该图范围未检测到文字）」，
并且不生成 `outside_info.json` / `outside_text.txt`（位图没有文字层）。
